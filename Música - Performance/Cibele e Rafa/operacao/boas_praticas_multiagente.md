# Boas Praticas Multiagente

## Ordem De Leitura
1. `README.md`
2. `AGENTS.md`
3. `identidade/pesquisa_publica.md`
4. `identidade/posicionamento.md`
5. `repertorio/README.md`
6. `conteudo/README.md`
7. `midia/README.md`

## Como Trabalhar
- Fazer mudancas pequenas e rastreaveis
- Nao reescrever arquivos de outros agentes sem necessidade
- Preferir criar novos docs de apoio a esconder informacao dentro de um unico arquivo gigante
- Atualizar os indices quando um novo documento importante aparecer
- Registrar premissas e pontos a confirmar

## Convencoes
- nomes de arquivo em ASCII
- use `lowercase` com `underscore` ou `hifen`
- outputs gerados em pasta com data
- dados brutos separados de dados aprovados
- todo material publico precisa de um status claro

## Quando O Agente Nao Tiver Certeza
- marcar como `a confirmar`
- nao inventar foto, link, bio ou credito
- se precisar pesquisar na web, guardar o achado em `identidade/pesquisa_publica.md`

## Para Setlists
- partir do tipo de evento
- checar duracao
- checar energia desejada
- respeitar tons de conforto
- montar primeiro o esqueleto do show e depois refinar blocos

## Para Conteudo Curto
- identificar a musica e o trecho
- registrar a origem
- escrever legenda com gancho
- guardar o material por estado

## Checklist Antes De Entregar
- o arquivo certo foi editado
- a informacao nova foi documentada
- nao houve sobrescrita acidental
- o texto ficou curto e usavel para outros agentes
